# 新製品記事の自動づくり(予定タスク charge-new-article)

2026-11-26 本人「A案で作る」。月・水・金の朝5時半に予定タスクが動き、新製品記事を1本書いて公開する。上限の週3本と同じ回数。
ユーザーは寝ている時間なので、質問せずに最後まで進める。迷う物は書かずに報告へ回す。

## 1. 今週の本数を数える

`content/p/` の `date:` を見て、今週(月曜〜)に出した記事が3本あれば、書かずに終わる。

## 2. 書く物を決める(上から順に)

1. **記事の無い控え**: `data/picks.yaml` にあり、製品データ(`data/products/<id>.yaml`)はあるのに `content/p/` に記事が無い物。11/26 時点で SHARGE P7U(`sharge-p7u`)・モンタップ(`elpa-montap`)・しろちゃんケーブル(`elecom-mpa-ccecdf10bf`)の3つ。この3つは古い順に1本ずつ
2. **新しく出た物**: 次のメーカーの公式ニュース・新製品ページで、直近1か月に発表・発売された物を探す。エレコム・バッファロー・サンワサプライ・Anker Japan・CIO・UGREEN・cheero・オウルテック・SHARGE・ELPA・ラディウス・MOTTERU など
   - `docs/WRITING.md` の「載せる新製品の選び方」の4つ(新しい技術・ギミック・数字で尖っている・見えないものが見える)のどれかに当たる物だけ。「載せない物」に当たる物は外す
   - すでに `data/products/` にある物(図鑑の物を含む)に記事を書いてもよい。ただし発売から3か月以内の物だけ
   - 直近の3本と同じカテゴリが続かないようにする(タップ・充電器・バッテリー・ケーブルを散らす)
3. 当てはまる物が無ければ書かない。数を埋めにいかない

## 3. 書く

- 書き方・製品データの決まりは `docs/WRITING.md` のとおり。公式ページと取扱説明書で確かめた事実だけ。使った感想は書かない
- 製品データが無ければ作る(同時出力の表は取説から全部写す。写真は公式の物を複数、白の色があれば白も)
- `stores:` は楽天・Amazon・Yahoo! を検索して、売っていれば入れる(買うボタンを付ける)
- 記事のファイル名は `content/p/<今日の日付>-<id>.md`、`date:` は今日

## 4. 本人に回すもの(公開しない)

次に当たるときは、記事を `draft: true` にして公開せず、状況メモ(`cockpit/status/tap-mania.md`)の「あなた待ち」に1行足す。

- 記事の中心が安全の話(消火・発火を防ぐ仕組み・事故・リコール・法律の説明)
- PSE を「確認済」にしたいが、公式の資料で確かめきれない(「未確認」のまま出すのは可)

## 5. 公開する

1. `python scripts/build.py` が通り、ページ数が1〜2増えていること、終わりの警告に新しい物が出ていないことを見る
2. 新しい記事のページを headless Chrome で 375px と 1280px で開き、横にはみ出さないことを確かめる
3. `git add` → `git -c commit.gpgsign=false commit`(最後に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`)→ `git push`
4. GitHub Actions の公開が通るのを `gh run watch` で待ち、本番の URL が開くことを確かめる
5. 状況メモの「現在地」の記事の本数と `updated:` を直す。「次にやること」の SHARGE・モンタップ・しろちゃんの行は、3本とも出たら `## 済み` へ移す

## 守ること

- git のグローバル設定は触らない
- 壊れた記事を公開しない。直せないときは途中でやめて、どこで止まったかを報告する
- 安全に関わる数字・PSE の「確認済」・事故件数・リコール・法律の説明は、本人が見てから出す(CLAUDE.md の決まり)
