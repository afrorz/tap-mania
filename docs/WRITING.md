# タップマニアの書き方

電源タップと延長コードを、取扱説明書の数字まで読んで並べるサイト。
収益は紹介料。読んだ人が「自分の使い方に合う1台」を見つけ、迷わず買えるようにする。ただし、安全に関わる情報を扱うので、**数字の正しさが紹介料より先**。

## 誰に向けるか

- **読者はガジェット好き(2026-11-12 本人判断)。** USB-C・GaN タップでデスクの電源を組む人。ノートPC・スマホ・タブレットをまとめて充電し、「65W と書いてあるのに2台目を挿すと何Wか」を気にする人
- 仕様書(11/11)にあった「入口は家の電源が不安な一般の人」はやめた。安全の話(寿命・1500W・雷ガード)は、ガジェット好きが買う前に確かめたい疑問として書く
- 防災(UPS・ポータブル電源)は、ガジェット好きの隣の関心として扱う
- この層は「実際に測った数字」を好む。実機を使っていないぶん、取説の表を全部写す・全機種で並べる細かさで差をつける。実測を足す時期は「判断の節目」(CLAUDE.md)のとおり

## 扱う物(2026-11-12 本人「モバイルバッテリーと USB-C・GaN 充電器も対象に」)

| category | 物 | 図鑑の表に出る項目 |
|---|---|---|
| `usb-tap` `tap` `extension` | 電源タップ・延長コード | 定格・口数・コード・シャッター・雷サージ・USB |
| `charger` | USB-C・GaN 充電器(コンセントに直接挿す物) | 入力・折りたたみプラグ・USB・大きさ・重さ |
| `battery` | スマホ用のモバイルバッテリー | 容量(mAh・Wh・定格容量)・電池の種類・入力・パススルー・安全の機能・USB・重さ |
| `ups` `power-station` | UPS・ポータブル電源 | (まだ形を決めていない) |

- 充電器は `input`・`size`・`weight_g`・`foldable_plug`、バッテリーは `battery: {mah, wh, rated_mah, cell, input_w, recharge_time, passthrough, safety}` を書く
- 安全の機能・電池の種類(準固体・リン酸鉄など)は、公式の言葉どおりに写す。「燃えない」「安全」と言い切らない
- PSE は `pse.mark` で形を書く。タップ・充電器はひし形(`diamond`、届出事業者名と登録検査機関名が要る)、モバイルバッテリーは丸形(`round`、登録検査機関名は要らない)。**この区分はサイトに説明として書く前に、経産省の原文で確かめる**
- モバイルバッテリーはリコールが多い。消費者庁・NITE に加えて、メーカー公式の自主回収のお知らせも型番で引く

## 看板: USB-C の配り方の全機種表(`/usb-c/`)

- 製品データの `usb.sharing`(同時に挿したときの配り方)から自動で作る。USB-C 付きの機種を足すたびに表が育つ
- `sharing` は公式に載っている組み合わせを**全部、原文の数字どおり**に写す。どこから取ったかを `sharing_source` に書く
- ポートの名前(`name: C1` など)はメーカーの呼び方に合わせる

## ページは3種類

| 種類 | 場所 | 中身 |
|---|---|---|
| 図鑑 | `data/products/<id>.yaml` → `/t/<id>/` | 1機種1ページ。表と短い補足。型番の検索(「◯◯ 何Wまで」)を拾う土台 |
| 比べ表 | `config/site.yaml` の `compare_views` → `/compare/` | 全機種と用途別。公式に記載のある項目だけ埋める |
| 疑問記事 | `content/q/<英小文字の短い名前>.md` → `/q/<名前>/` | 疑っている人の検索に一次情報で答え、最後に合う機種へつなぐ |

### 疑問記事の候補(検索サジェストで確かめた語)

1. 雷ガードは意味ないのか
2. 寿命3〜5年は嘘か(メーカー別の公称値を並べる)
3. 1500W を超えるとどうなるか(済: `content/q/1500w.md`)
4. USB-C 付きタップの出力の配り方(全機種の表)
5. マグネットのタップを後付けして大丈夫か
6. ほこりシャッターは必要か、トラッキング火災とは
7. 3ピンと2ピンの違い、アースは要るか
8. たこ足配線は何個までか

## 絶対に破らない決まり(Gadget Terminal・Cozy Desk と同じ)

- **公式ページ・取扱説明書で確かめた事実だけ書く。** 数字には出典 URL と取得日を残す(記事は front matter の `sources:`、製品は `official_url`・`manual_url`・`checked`)
- **値段には「掲載時点」と付ける。** 日本で買える物は円で、公式ストアか希望小売価格。一時的な値引きは書かない
- **画像はメーカー公式ページ・公式ストアの画像 URL を直接書く**(ダウンロードしない)。出典を書く。ニュースサイト・個人ブログ・Amazon の画像は使わない。開けることを確かめる(`python scripts/check_images.py`)
- **使った感想を書かない。** 「使ってみると」「手に取ると」は禁止。「レビュー」「検証」「使ってみた」と名乗らない(実機を使っていない)
- 煽らない。感嘆符と絵文字を使わない

## このサイトで足す決まり

- **言い切り禁止の言葉**: 「絶対安全」「火災を防ぐ」「雷から守る」。言い換えは「メーカーは◯◯機能を搭載と記載している」「NITE は◯◯を勧めている」
- **事故の件数**は NITE の原文 PDF から取り、「期間・数えた範囲(重大事故だけか、そうでないものも含むか)・発表日」とセットで書く。報道記事から取らない
- **リコール**は、消費者庁リコール情報サイト(https://www.recall.caa.go.jp/)か NITE で**型番が一致した場合だけ**書く。似た型番・同じメーカーというだけで結びつけない
- **寿命**は「日本配線システム工業会(JEWA)の推奨で交換目安3〜5年。保証期間や耐用年数ではない」と正確に書く(出典: パナソニック https://panasonic.jp/tap/support.html 。JEWA 本体のページは未確認)
- **1500W** は「多くの製品が 15A・125V の定格であることから来る数字」。製品ごとには公式の定格を書き、一般論で断定しない。壁のコンセントは2口の合計で 1500W まで(NITE 2024-01-25)
- **雷サージ**は、公式に記載された内容(素子・耐量・規格)だけを書く。効果を断定しない
- **USB の出力**は、ポートごとの最大と、同時に使ったときの配り方を書く。合計Wだけを書かない
- 公式と取説で数字が食い違うときは、両方を出典つきで `note` に書き、どちらかに決めつけない(例: サンワ TAP-B115UC-2BK の4ポート同時の出力)
- 文の調子: やさしい「です・ます」。専門用語は避けるか、初めて出るところで一度だけ説明する(例: 「PSEマーク(国の安全基準を満たした印)」)。マニアらしさは言葉の熱さではなく**数字の細かさ**で出す

## AI が書いてよい範囲と、本人が見る範囲

| AI が書いてよい | 本人が確認してから出す |
|---|---|
| 公式の数字を出典 URL・取得日つきで写す | PSE を「確認済」とする判定 |
| 比べ表を作る | 事故の件数、リコール |
| NITE・経産省の一般的な注意を引用する(引用元を固定) | 「◯年で交換」などの安全に関わる数字 |
| | 法律の説明 |

右の列を含む記事は、本人が見るまで front matter に `draft: true` を付けておく(ビルドでページが作られない)。本人の OK が出たら外す。

## PSE 三点照合(このサイトの「確かめる軸」)

電源タップ・延長コードは電気用品安全法の**特定電気用品**(配線器具)にあたり、本体に次の3つがそろっている必要がある。

1. ひし形の PSE マーク
2. 届出事業者名
3. 登録検査機関名

| `pse.status` | 表示 | 意味 |
|---|---|---|
| `confirmed` | 確認済 | メーカー公式ページか取扱説明書の PDF で確認した |
| `image` | 公式画像で確認 | 公式の製品画像で、本体の表示(銘板)の3点が読めた |
| `unconfirmed` | 未確認 | 確かめられなかった。**紹介リンクを貼らない**(build.py がボタンを消す) |

- 楽天・Amazon の商品ページの記載や、公式ページの「PSE適合 あり」という文字だけでは「確認済」にしない(マーク・事業者名・検査機関名が読めて初めて)
- 確かめた方法(`pse.how`)と日付(`pse.date`)を必ず残す。`confirmed`・`image` なのに無いとビルドが止まる
- 2025-12-25 施行の改正製品安全4法で、モール経由で直接売る海外事業者も届出の対象になった(国内管理人が必要)。「販売者・届出事業者が国内で特定できるか」も `seller_jp` に書く
- **裏取りの残り**: 経産省のページは仕様書の調査時に本文が開けなかった(403)。サイトに法律の説明を載せる前に、次の原文を開いて確かめる
  - 延長コードセットの解釈: https://www.meti.go.jp/policy/consumer/seian/denan/kaishaku/taishou_hitaishou/20250214/KIGUYOUSASIKOMIPURAGU.pdf
  - 表示事項: https://www.meti.go.jp/policy/consumer/seian/denan/procedure_08.html
  - 登録検査機関一覧: https://www.meti.go.jp/policy/consumer/seian/denan/cab_list.html

## 製品データの書き方

1ファイル1機種。`id` はファイル名と同じで、URL にも使う(英小文字・数字・ハイフン)。

```yaml
id: sanwa-tap-b115uc-2bk
maker: サンワサプライ
model: TAP-B115UC-2BK
name: "(公式の製品名)"
category: usb-tap                  # tap / extension / usb-tap / charger / ups / power-station
image: "https://…"                 # メーカー公式の画像 URL(ダウンロードしない)
image_credit: "サンワサプライ 公式サイト"
official_url: "https://…"
manual_url: "https://…"            # 取扱説明書の PDF。あれば必ず
checked: 2026-11-12                # 最後に公式情報を見た日
pse:
  status: confirmed                # confirmed / image / unconfirmed
  how: "取扱説明書 p.2 の表示"
  notifier: "(届出事業者名)"
  inspector: "(登録検査機関名)"
  date: 2026-11-12
rating: {volt: 125, amp: 15, watt_max: 1500}   # 定格。公式の数字だけ
cord: {length_m: 2, type: "VCTF"}             # type は公式に記載がある場合だけ
outlets:
  ac: 4
  shutter: true                    # ほこりシャッター。公式の呼び方は note に
  tracking_plug: true
  switch: individual               # none / all / individual
  three_pin: false
  rotating_plug: false
  magnet: false
surge: {has: true, spec: "(公式に記載された耐量・素子・規格。無ければ書かない)"}
usb:                               # USB 付きのとき
  ports:
    - {name: C1, type: C, max_w: 65}   # name はメーカーの呼び方
    - {name: C2, type: C, max_w: 30}
  total_w: 65
  sharing:                         # 同時に挿したときの配り方。公式の組み合わせを全部。合計Wだけを書くのは禁止
    - {use: "C1+C2", out: "45W+20W"}
  sharing_source: "取扱説明書 p.4 の表"
  pd: true
  pps: true
  gan: true                        # 公式に GaN と書いてあるときだけ
flame: "UL94 V-0(どの部分かも書く)"
colors: [ブラック, ホワイト]
warranty: "1年"
seller_jp: "(国内の販売者・連絡先が特定できるか)"
recall_checked: 2026-11-12         # 消費者庁リコール情報サイトと NITE で型番を引いた日
recall: none                       # none、または該当するリコールの URL
stores: [rakuten, amazon, yahoo]   # 正規に売っている店だけ。書いた店のボタンだけ出る
q: "TAP-B115UC-2BK"                # 3つの店の検索でその物が一番上に出る言葉。実際に検索して確かめる
price: "(円。掲載時点・公式ストアか希望小売価格)"
note: |
  公式の呼び方や補足。推測は書かない
```

- 項目は「公式に記載あり」なら書き、「記載なし」なら**キーごと書かない**(画面には「記載なし」と出る)
- `checked` が180日より古い製品は、ビルドの最後に一覧が出る。値段と仕様を見直して `checked` を更新する

## 疑問記事の書き方

```yaml
---
title: 電源タップは何Wまで使える？1500Wを超えるとどうなるか
date: 2026-11-12
summary: "検索結果に出る1〜2文"
face: shinpai            # 冒頭のタプ夫の表情(futsu / shinpai / odoroki / majime / ureshii)
intro: タプ夫の冒頭のひとこと(安全の事実は入れない)
products: [sanwa-tap-b115uc-2bk]   # 記事の最後に並べる機種。図鑑の「この製品にかかわる疑問」にも出る
sources:
  - {name: "NITE「…」(2024-01-25 発表)", url: "https://…", date: 2026-11-12}
---
```

本文で使える札(1行に札だけを書く):

| 札 | 出るもの |
|---|---|
| `{{tool:watt}}` | 消費電力の計算機への案内(タプ夫つき) |
| `{{appliances}}` | 家電の消費電力の目安表(`data/appliances.yaml`) |
| `{{products}}` | front matter の `products` の機種カード。`{{products:id1,id2}}` で個別に指定 |
| `{{tapuo:odoroki\|ひとこと}}` | タプ夫の吹き出し(安全の事実は言わせない) |

- 一次情報(NITE・経産省・メーカー)で答え、最後に合う機種(図鑑のページ)へつなぐ
- 家電の消費電力の目安は `data/appliances.yaml`。出典は `sources` に1行足して `source` で指す。個人ブログ・まとめサイトの数字は使わない

## タプ夫

| 項目 | 内容 |
|---|---|
| 名前 | タプ夫(たぷお) |
| 見た目 | 頭が日本の「アース付き三ツ口コンセント」、体は人間。約2頭身 |
| 顔 | 縦の2つの差し込み口が目(左の目が右より長い)。下のアース穴が口 |
| 服 | オレンジのパーカー、黒いパンツ、白いスニーカー。黒い本(取扱説明書)を持つ |
| 一人称・口調 | 僕。「〜なんだよね」「ここ、誰も見てないんだよ」。くだけているが、なれなれしくない |
| 口ぐせ | 「取説、最後まで読んだ？」 |
| 安全の話のとき | 表情を「まじめ」にし、冗談を言わない |

- **言わせる**: 記事の冒頭のひとこと、道具の案内、X の投稿
- **言わせない**: 事故の件数、リコール、法律の説明など安全の事実。これは本文に普通の文で書く
- 「みつくち」という呼び方は使わない(口唇裂を指す差別語)
- 「左の穴が少し長い(接地側)」は、JIS などの一次情報で裏を取ってから書く

| 表情 | ファイル | 使う場面 |
|---|---|---|
| ふつう(手を振る) | `assets/chara/tapuo-futsu.png`・`face-futsu.png` | サイトの顔、X のアイコン |
| しんぱい(困り眉) | `…-shinpai.png` | 寿命・ほこり・たこ足配線の話 |
| おどろき(目が縦に伸びる) | `…-odoroki.png` | 「取説の12ページにこんな数字が」 |
| まじめ | `…-majime.png` | 安全の話、PSE の無い製品の話 |
| うれしい(手を振る) | `…-ureshii.png` | いい新製品が出た、選び方がわかった |

## 広告の表示(景品表示法・ステマ規制)

- 紹介リンクのあるページには、**冒頭とリンクの近く**に「広告を含みます」と出す(build.py が自動で出す。`affiliate:` が空のあいだは出ない)。消費者庁の Q&A で、冒頭だけでは足りない場合があるとされているため
- 紹介リンクには `rel="sponsored noopener"`(build.py が付ける)
